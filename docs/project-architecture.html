01 / 分层架构：控制面冻结过程，数据面构造样本

业务链路由阶段处理器实现；计划器固定依赖、分片和签名，运行器负责执行缺失分片。模型部署服务负责推理，金融环境负责工具、证据与答案校验，两者各有独立记录。

控制面计划 · 调度 · 恢复

配置与辅助文件

v3 YAML、模型角色、截止日、质量门槛、公式、实体别名、任务种子、自定义工具。

Planner → 冻结 plan.json

扫描输入、打包 normalize 分片、检查公式/种子匹配，固定阶段依赖及上下游签名。

Runner / Worker

当前机器或 SLURM 作业执行；阶段按计划顺序推进，同一阶段内可并行分片。

数据与知识层保留出处

JSONL / Parquet 语料

正文与可用日期、实体等元数据；normalize、ID 冲突校验、正文去重后切块。

结构化事实池

extractor 抽取事实，保留 source_id、chunk_id、引文；实体解析后按实体重分区。

公式与种子约束

公式确定可执行运算；任务种子约束目标类型、事实角色和推理形式。事实数值来自原始语料。

合成与验证层先有可解结构

证据 DAG 规划

从已对齐事实实例化可用公式，形成证据叶节点与计算节点，保留来源和标准答案。

Query 实现与原子分支

constructor 将 DAG 和任务种子实现为问题；可选 atomic 从单个 chunk 及其事实构造局部能力任务。

结构、重放与语义验证

检查证据与答案图，执行运算重放并做审计；配置启用时进行评测题去污染。

执行与教师层可选生成轨迹

冻结语料与检索索引

从 chunks 构建 SQLite 快照，并结合实体分区事实建立检索索引，固定 cutoff 与来源。

Native / Strands / Codex / CC

保留不同的 agent loop；Strands、Codex、CC 支持金融与原生两种工具模式。外部 runtime 保留协议层轨迹。

在线环境 / 离线校验

金融模式由 HarnessSession 管理动作、预算和账本；原生模式在语料文件中研究，结束后绑定真实读取并校验证明。

发布层按用途分离

Query 数据

train/val 只有 query；隐藏校验单独保存任务、证据、答案图与快照引用。

按协议分别输出

atomic / 金融 long 使用统一 messages；原生 Codex、Strands、CC 保留各自逐请求协议。私有审核放在 sidecar / native audit。

审计与发布清单

保存成功/失败轨迹、质量统计、文件大小与可选 SHA-256，再写 _PUBLISHED.json。

“证据 DAG”表示单个问题的推理与计算依赖；下节的“阶段依赖”表示工程流水线的执行顺序，二者是不同层级。

02 / 阶段依赖与两个交付分支

下表对应 workflow/planner.py 的阶段计划。实际启用的阶段由配置决定；阶段名称、分片数与依赖在创建计划时固定。

阶段直接依赖职责与主要中间结果
normalize输入分片 assignments规范化记录；按扫描结果和目标分片字节数分配输入工作。
id_validation → dedupID 校验读 normalize；dedup 读 normalize + ID 校验识别同一外部 ID 的内容冲突，再对规范化正文去重；两类问题分别统计。
factsdedup切块、调用 extractor、校验出处，写 chunks 与结构化事实。
atomic 可选facts从事实构造原子候选，与长程任务在 validation 汇合。
entity_resolution → repartitionfacts → entity_resolution解析规范实体与别名，按实体 ID 重分区，同一实体的多来源事实可共同规划。
graph_planning → query_realizationrepartition → graph_planning先按种子约束选择公式，再结合事实生成答案图和具体 TaskSpec，回放通过后实现问题表述。
validation已启用的 atomic / query_realization审核任务、证据、计算与问题一致性，保存合格任务及拒绝原因。
corpus_index → retrieval_indexfacts；retrieval 还依赖 repartition全局 chunks 建快照；按实体事实建立分区检索索引。
query_export 可关闭validation + retrieval_index输出纯 query、隐藏 verifier 和快照清单，不依赖教师执行。
sft_prepare 可关闭validation；启用 long 时还依赖 retrieval_index筛选任务、执行教师、校验证明、规范化 messages，保存每次长程尝试。
exportvalidation + 已启用的 query_export / sft_prepare检查全局质量和数量门槛，汇总任务、query、SFT 和轨迹，提交发布清单。
QUERY

先交付可验证的问题

validation + retrieval_index → query_export。模型输入为纯 query，隐藏校验与快照由外部使用者单独加载。教师合成失败时，已经完成的 query 分片仍可使用。

只生成 query：关闭 training.enabled 与 atomic.enabled，保留 query_export.enabled。

TEACHER SFT

按需交付实际执行轨迹

validation + retrieval_index → sft_prepare。长程教师通过金融或框架原生工具取得证据，证明通过校验后进入对应格式的样本文件。原子教师生成自然语言和可见 CoT，经内容审核及 judge 择优；已审核参考 r 作为独立来源参与 SFT。

两条分支独立产出；最终 export 等待所有已启用分支完成。

金融模式的 submit_final(answer) 转为 final 动作；检查引用、计算与答案，合格后输出统一金融 SFT。

同一任务与校验约束

金融模式每次尝试创建独立 session，调用进入专属线程；原生模式使用独立工作目录，Strands 另用子进程隔离。两者都不向模型暴露私有 grade() 或 gold DAG。

最终证明才是验收依据

CLI 返回 0 或 SDK 自然结束不足以接纳轨迹。金融模式校验最终提交，原生模式校验最后正常回复及真实来源读取；还需确认模型 HTTP 采集完整。

教师选择有停止条件

按配置轮换长程教师角色，首条合格轨迹出现后停止该任务的后续尝试。多角色配置不代表每个任务都运行全部 runtime。

自定义工具通过注册表扩展，定义、实现与声明资源纳入辅助指纹。接口见 Harness 文档，runtime 配置与限制见 教师 runtimes 文档。

04 / 三层轨迹：调用内容、框架执行、证据状态

部署后端记录收到的请求与返回内容；完整合成审计还需要框架事件和取证记录。金融模式导出统一 messages，原生模式保留各协议的逐请求输入与输出，分别发布。

Agent 决策

SDK/CLI 发出模型请求，处理返回，决定下一步工具调用。

→

本地 TraceProxyServer

外部 runtime 每次尝试自动启动；转发 HTTP，保留请求/响应/SSE 字节与时间。

→

模型部署服务

vLLM/SGLang 或兼容网关，提供该 runtime 所需协议、工具 parser 与 chat template。

L1 · MODEL

模型协议层

保存实际 prompt、工具定义、采样字段和服务返回的文本/工具调用/SSE。服务返回哪些 token、logprob 或 reasoning 字段，就保留哪些字段。

model/run.json
model/calls/*

不会从文本反推 token IDs，也不生成服务未返回的内部推理内容。

L2 · RUNTIME

框架执行层

Strands 保存 SDK 回调与消息历史；Codex/CC 保存 JSONL/stream-json 和诊断，可解释调用次序、框架状态与失败位置。

agent.events.jsonl
agent.messages.json
或 stdout.jsonl / stderr.log / cli.json

L3 · ENVIRONMENT

证据与校验层

金融模式保留动作、观察与账本；原生模式保留语料完整性、原生读取绑定和离线 verdict。实际解答经私有语义审核和候选运算回放，证据来自真实观察；接受等价路径，错误、重复及无贡献动作按轮次屏蔽监督。

environment.json / result.json
native-workspace.json / native-audit.json

隐藏答案与校验结论不进入模型输入。

统一金融样本与原生协议样本分别发布。

金融 long messages 绑定模型实际文本、调用与环境结果；原生模式按每次真实请求导出 Codex Responses items、Strands Chat Completions messages 或 CC Anthropic 内容块，保留工具原名和 schema。项目 native 的完整请求与响应 JSON 在 model/calls，可来自完整响应缓存；model.parsed.json 仅为兼容摘要。

每次长程尝试都写轨迹引用，包括失败和超时。外部 runtime 停止后检查采集代理是否空闲，再冻结记录，避免迟到流式响应修改已发布文件。原始轨迹可能包含完整来源内容，HTTP 凭据头脱敏不等于正文通用脱敏。

06 / Linux 运行拓扑与资源边界

代码可在工作站编写，批量合成部署在 Linux。worker 通过 HTTP 调用模型服务，自身不要求加载模型权重；GPU 由 vLLM/SGLang 的部署管理。

单机 / Linux 服务器

python3 -m pip install -e .
# 使用 Strands 时安装可选依赖
python3 -m pip install -e '.[strands]'
mint-synth config validate --config config/production.yaml
mint-synth run --config config/production.yaml --workers 4

Python 3.10–3.13；CLI runtimes 需预先安装 Codex/Claude Code，固定可执行文件和版本。

SLURM：单作业调用相同运行器

mint-synth plan --config config/production.yaml
export MINT_PYTHON=/shared/venv/bin/python
export MINT_WORKERS=4
bash scripts/submit_slurm.sh /shared/outputs/runs/<run_id> \
  --partition=compute --cpus-per-task=8 --mem=32G

唯一作业脚本 slurm/mint-synth.sbatch 调用 run --run-dir；SLURM 资源参数留在脚本和环境变量，不写入合成 YAML。

并发分为两层

--workers 控制当前阶段的分片进程；角色客户端按 llm.concurrency_per_worker 处理并发。

CLI/SDK 还有自身请求行为，实际峰值取决于当前阶段与 runtime，不能统一用两配置值相乘推定。

本地代理与工具服务

每次外部教师尝试启动 loopback 采集代理；CLI 金融模式另连接带 token 的 finance MCP。原生模式直接使用语料文件，不创建 MCP。容器内须能访问本地代理。

协议兼容是部署条件

Strands 需要 Chat Completions 工具调用；Codex 需要 Responses；CC 需要 Anthropic Messages。模型服务或网关须提供对应协议，并匹配工具 parser 与模板。

执行配置与内容审核分别负责。

CLI 使用独立临时 HOME 和工作目录。web 模式允许原生搜索、网页访问和用户配置的 MCP，不按项目工具白名单筛选。静态和旧金融模式保留兼容接口；Codex 保留配置的 sandbox，Strands 在独立子进程加载官方或自定义工具。实际调用与观察保留原格式，来源、时间和解答通过共同审核；不重新执行任意 shell 命令来校验结果。

07 / 可恢复与可追溯：冻结、缓存、提交、发布

01 · FREEZE

冻结输入与实现版本

plan.json 记录输入目录、配置、代码与辅助指纹；公式、种子、别名、评测题与自定义工具资源一并校验。

分片签名包含阶段、分片 ID、normalize 输入分配及上游聚合签名，计划本身有完整性指纹。

02 · REQUEST CACHE

重用角色文本与 JSON 请求

SQLite 缓存按 run/stage/shard/model role 隔离；键包含角色命名空间、system/user、采样参数与 sample_key；文本另有模式和版本，不复用旧 proof 缓存。immutable 保留首次写入，refresh 重新请求。

缓存服务于项目角色客户端和 native 教师；外部 SDK/CLI 的 HTTP 采集本身不提供响应缓存。

03 · COMMIT

原子提交已完成分片

worker 验证计划和上游，写临时目录后提交 _SUCCESS.json。失败保留记录，不完整分片可隔离重做。

同一 run 的运行锁阻止并发 runner 写入；恢复时校验签名和产物完整性，再复用完成分片。

04 · PUBLISH

质量门槛之后发布

检查无效记录率、ID 冲突率、LLM 终态错误率、验证拒绝率与最小数量，确认启用的 query/SFT 交付门槛。

文件清单核验后写 exports/manifest.json 和 _PUBLISHED.json；已提交 export 可用于恢复发布标记。

mint-synth run --run-dir /shared/outputs/runs/<run_id> --workers 4
mint-synth status --run-dir /shared/outputs/runs/<run_id>
mint-synth validate --run-dir /shared/outputs/runs/<run_id>

输入、辅助文件或实现改变后应创建新计划；旧计划由对应代码与冻结输入继续执行。签名和缓存提高可追溯性，不能保证远端模型在不同版本与硬件上重新采样完全相同。
