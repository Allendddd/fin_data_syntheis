项目架构与运行方式

v3 从原始金融语料构造可验证的长程 query。可选的教师数据阶段让强模型在本地冻结的语料快照和工具 harness 中执行 query，并输出 SFT messages。运行入口与调度器分离。

使用说明 构造方法 query 数据契约 SFT 轨迹 SLURM 提交

运行路径

本地机器

mint-synth run --config config/production.yaml --workers 1

创建冻结计划，依计划顺序执行阶段。在同一阶段内，--workers 控制分片进程数。

SLURM 集群

mint-synth plan --config config/production.yaml
bash scripts/submit_slurm.sh <run_dir> [sbatch options...]

提交一个作业。slurm/mint-synth.sbatch 使用计算节点的 Python 调用同一个 run --run-dir 入口；资源和解释器由脚本及环境变量指定。

再次调用 run --run-dir <run_dir> 时，运行器根据计划签名与完整性检查跳过已完成分片。运行目录锁避免两个进程同时写入同一计划。

v3 数据阶段

输入整理

normalize → ID 校验 → 去重

→

证据构造

事实抽取 → 实体解析 → 重分区

→

任务构造

evidence DAG → query 实现 → 验证

可选的原子任务从事实分支生成，并汇入验证阶段。实际启用的阶段、分片数与依赖关系由计划文件固定。

长程 query 分支

冻结语料索引 → 检索索引 → query_export

输出只含 query 的 train/val JSONL 和独立的隐藏答案校验文件。该阶段依赖已验证任务与检索索引，可先于教师轨迹完成。

教师 SFT 分支，可关闭

sft_prepare 让强模型执行 query，使用 search_corpus、open_chunk 与 calculate。轨迹通过证据与答案门控后转换为 messages。

最终 export 汇总启用的分支并检查质量门槛，写入发布清单。外部 OPD 流程使用纯 query；本项目不运行学生训练。

代码职责

core + storage

配置与指纹、运行目录、输入读取和规范化。

synthesis + inference

事实、实体、DAG、query、审计，以及模型角色与请求缓存。

harness + sft

冻结语料工具、教师执行、轨迹审核和 messages 格式化。

workflow

计划、阶段处理器、worker、本地运行器、query 导出和发布。

SLURM 仅在仓库的一个作业脚本和一个提交脚本中出现。合成 YAML 不包含调度字段。旧 v2 配置仍保留读取能力；旧计划须使用创建它的代码版本继续执行。

运行目录

runs/<run_id>/
  plan.json                 冻结阶段、依赖与分片签名
  resolved_config.yaml      展开后的数据配置
  assignments/              输入分片分配
  stages/<stage>/shards/    分片产物和 _SUCCESS.json
  logs/                     分片日志与可选 SLURM 日志
  exports/manifest.json     最终发布清单
  _PUBLISHED.json           发布标记

分片在同一文件系统内先写临时目录，再原子提交。LLM 请求缓存支持失败分片恢复；输入、辅助文件和代码指纹阻止错误版本续跑。
