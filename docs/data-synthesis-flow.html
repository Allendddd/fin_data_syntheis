Grounding and provenance

02 · 原始数据如何进入系统

一条输入记录可以产生零到多条任务；长程任务会组合多份记录的事实。文件、记录、chunk、fact 和 task 各有独立 ID。

贯穿示例：两份已公开的年度披露

{
  "id": "demo-2025",
  "text": "云帆科技2025年营业利润为18亿元，营业收入为120亿元。",
  "title": "云帆科技2025年度披露",
  "ticker": "DEMO001",
  "published_at": "2026-03-20"
}
{
  "id": "demo-2024",
  "text": "云帆科技2024年营业利润为12亿元，营业收入为100亿元。",
  "title": "云帆科技2024年度披露",
  "ticker": "DEMO001",
  "published_at": "2025-03-20"
}

演示中设 input.id_field: id，元数据保留 title / ticker / published_at，截止日为 2026-09-29。公司和数据均为虚构。原始 PDF / 网页的下载、OCR、表格解析需要在上游完成，本项目从整理后的文本记录开始。

除正文之外，还需要哪些输入

  • 来源元数据：title、URL、ticker / CIK / LEI、发布日期。元数据只能保留输入中原本存在的信息。
  • 种子 JSONL：query_realization.seed_file，可选；未指定时使用内置近似种子。
  • 公式 YAML：dag.formula_registry，默认 builtin；定义可执行模板及版本。
  • 实体别名 YAML：entity_resolution.alias_file，可选；控制名称归并。
  • 评测问题 JSONL：quality.evaluation_file，可选；只用于近重复排除，不作为合成示范或事实输入。
  • 配置：cutoff、角色模型、难度门槛、过滤标签、分片与输出位置。

种子库、别名、公式与评测文件的内容指纹会纳入冻结计划。改变这些输入需要创建新计划。

步骤具体处理输出 / 失败去向
发现与分片遍历配置文件；JSONL 按字节段规划且读取时对齐换行，Parquet 按 row group 规划。记录文件与段指纹。输入清单、normalize assignments
规范化检查 JSON object、text 类型和长度；保存外部 ID、元数据 JSON、来源 locator 与正文 SHA-256。正文不被改写为模型摘要。normalize/data.parquet；坏记录进入 quarantine
外部 ID 校验同一个 external ID 对应多个正文哈希时，将所有相关记录判为冲突；先按 ID 分区发现，避免内容分区漏检。conflicts.parquet + 隔离记录
全局精确去重排除冲突 ID 后，按正文哈希保留按来源位置稳定排序的一个代表。相同正文不会因不同文件名重复进入 LLM。dedup/data.parquet；这一步不做语义近重复
技术细节：稳定 ID、分区和来源定位

record_id 在存在 external ID 时由该 ID 稳定生成；未配置 ID 时由 source URI、locator 和 content hash 共同生成。事实阶段令 source_id = record_id。正文哈希用于去重，不能把 record_id 简写为正文哈希。

正文哈希先映射 dedup_bucket，再映射 shuffle_partition；external ID 使用独立分区键。Parquet 的大对象通常放在 envelope 的 JSON payload 中，外层稳定列支持分组、排序和 shuffle。

JSONL locator 包含行号及字节位置；Parquet locator 包含 row group 与行位置；chunk / fact 增加原文字符区间。字节位置与 Unicode 字符位置不能混用。

“至少两个独立来源”在当前实现中指至少两个去重后 source_id，不等于两个独立出版机构。精确去重也不能识别所有转载或语义改写。

source_uri输入文件位置
source_locator行 / 字节 / row group
record_id规范化记录与正文哈希
chunk_id原文字符范围
fact_id逐字引文与金融维度
graph_id / task_id公式、答案图与问题

实现：catalog.pyrecords.pyingest.py

Extract, localize, validate

03 · 从原文到可计算事实

extractor 只负责提出候选事实；代码检查逐字证据与显式值，再分配 fact_id。原文没有出现的计算结果不能提前伪装成披露事实。

切块与抽取规则

  1. 按段落、换行与标点边界启发式切块，默认最大 6,000 字符、重叠 400 字符、目标最小 600 字符；短文仍可成为一个 chunk。这一步不使用 embedding 聚类。
  2. extractor 每块返回最多 30 个候选，字段包括 entity、period、metric、value_num / value_text、unit / scale / currency、fact_type、quote。
  3. quote 必须是 chunk 的精确子串；value_num 必须与 quote 中显式数字匹配；value_text 必须是保真子串。
  4. 由 chunk 起点加 quote 的局部位置，得到原文全局字符区间；fact_id 包含来源、区间、实体、期间、指标、值和维度信息。
  5. 同一记录的重叠 chunk 若生成相同 fact_id，会再次去重。非数值事实可服务 Atomic，规则 DAG 只选可解析数值事实。

事实示例：2025 年营业利润

{
  "fact_id": "F25P",
  "source_id": "S25",
  "chunk_id": "C25",
  "entity": "云帆科技",
  "period": "2025",
  "metric": "营业利润",
  "value_num": "18",
  "value_text": null,
  "unit": "元",
  "scale": "亿",
  "currency": "CNY",
  "fact_type": "reported",
  "quote": "云帆科技2025年营业利润为18亿元",
  "locator": {"char_start": 0, "char_end": 18}
}

F25P / S25 / C25 是为讲解缩短的 ID；实际系统用稳定哈希 ID，locator 还保留文件来源字段。

数值和引文定位检查能阻止许多幻觉，但不能证明模型识别的指标、单位、实体和期间一定正确。维度兼容、语义 auditor 与人工抽样仍然必要；当前系统不会自动把任意币种、金额倍率或会计口径换算为一致。

Seed as intent and constraints

04 · 种子如何真正参与合成

种子是任务规格来源：它在 DAG 规划前生效，也在问题实现和去复制审核时使用。最终数值来自原文事实与图回放。

用于贯穿示例的自定义种子

{
  "seed_id": "seed_margin_change",
  "seed_query": "比较同一公司的两个报告期营业利润率，给出变动的绝对幅度。",
  "task_spec_template": {
    "objective_type": "change",
    "reasoning_form": "retrieve a same-scope ratio across periods and compute its absolute change",
    "required_fact_roles": [
      "new_period_numerator",
      "new_period_denominator",
      "old_period_numerator",
      "old_period_denominator"
    ],
    "time_sensitive": false,
    "requested_output": "absolute magnitude of the operating margin change"
  },
  "origin": "user_seed_bank"
}

实际 seed 文件是 JSONL，每条对象占一行。此处展开排版。配置 query_realization.seed_file: /data/seeds/analyst.jsonl 后使用。

从种子到具体任务的五步

  1. 加载：读取 seed_id、seed_query、task_spec_template、origin；未给 ID 时稳定生成。
  2. 预校验：v3 自定义种子必须带完整 template；检查 objective_type、reasoning_form 与 required_fact_roles 是否能映射到已实现 generator。
  3. 编译约束：本例的 change + ratio change + 四角色映射到 ratio_change，再选择注册公式 temporal_ratio_change。
  4. 约束规划：只对匹配拓扑和时间要求的事实构图；之后仍需满足深度、来源数和回放门。
  5. 实现问题：保留 seed 与具体 task_spec；constructor 参考种子意图和图摘要写问题，auditor 检查未照抄种子。

本例四事实比率变化需要上面的自定义种子。seed_file: null 的内置种子不会自动覆盖全部注册公式。

种子意图 / 推导形式映射 generator可用结构当前约束
change + 跨两期间变化temporal_pair新值与旧值相减 / 百分比变化，再取幅度内置 seed_change 可选择
change + 三期 trendtemporal_trend三事实、两次差分、均值、幅度需要相应自定义种子
change + ratio changeratio_change两期各形成比率，再求差与幅度需要相应自定义种子；本页示例

comparison当前无对应 generator未实现自由比较拓扑内置近似 comparison 种子跳过；不支持的自定义规格报错
技术细节：种子能力、筛选和回退的准确边界

reasoning_form 当前通过受约束的英文关键词与 objective_type 映射；required_fact_roles 经大小写、标点和下划线归一化后与允许的角色及顺序校验。这是规格编译规则，不能把任意自然语言种子当作可执行新算法。

种子不会提供 gold answer，不会直接复制旧任务答案，也不会自动生成任意复杂 DAG。当前 role 约束限制角色结构，并不把“营业利润”这样的业务指标名强制绑定到任意分子位置；具体指标仍来自公式候选匹配与语义审核。

种子顶层的 time_scope、financial_topic 不是当前加载器消费的字段。时间控制来自 run.cutoff 与 template.time_sensitive；金融主题由任务指标关键词派生，再由 training.financial_topics 筛选。

training.seed_ids、objective_types、formula_ids 等白名单会影响候选与后续导出；seed_fallback: true 且指定自定义 seed_file 时可补入内置种子，默认关闭。这个配置改变任务来源范围，不能作为静默放宽质量门。

类中保留的旧 LongHorizonSynthesizer.synthesize() 能让 LLM 先提图，但当前 v3 stage 主路径是 seed 约束 → RuleDagPlanner → query_realization，不应将旧方法调用顺序当作现行流水线。

实现：seed loader / 内置种子seed_constraints.pygraph_planning / query_realization

Evidence crossover and answer-first planning

05 · 同一实体的事实，如何变成答案 DAG

跨来源组合发生在 canonical entity 范围内。证据 DAG 描述答案的依赖和运算；它不是预先规定教师必须执行的检索路径。

① 解析与汇合主体

强标识符 → 版本化 alias → 名称规范化 → 受约束的 LLM 歧义回退。相同 surface 的强标识冲突进入隔离。

解析后按 canonical_entity_id 哈希重分区，让散落不同文件和 shard 的同主体事实进入同一个 planner。

② 枚举受约束候选

选择显式数值事实，按 generator 匹配指标、期间类型、单位、倍率、币种与来源宽度。年、季、半年和点时日期不会混配。

种子限定可用公式。候选扫描上限与有效候选 beam 分开，坏候选不会提前占完有效名额。

③ 执行与排序

fact 节点指向现有 fact_id；operation 节点引用父节点。Decimal 执行后检查深度、来源数与完整祖先。

规范图连同公式 ID / 版本生成稳定 graph_id；候选优先更多来源、更深结构，再稳定排序截断。

回放拒绝未知事实 / 节点、环、非法重复输入、除零、非有限数值和维度不兼容；图中所有节点都必须是 terminal 的祖先。声明 evidence_ids 必须与实际事实祖先完全相等，不能靠多挂证据或断开的深节点凑难度。

深度从事实叶 0 开始，operation 深度为父节点最大深度加 1；例中 ratio=1、subtract=2、abs=3。来源数只统计 terminal 真正依赖的事实来源。

本例“营业利润 / 营业收入”能形成该方向，依赖当前指标归一化名称排序恰好使利润排在收入前。ratio_change 生成器不会从任意 seed 文本自动理解并强制绑定财务分子 / 分母；不合理配对仍应由语义 auditor 拒绝。

技术细节：候选不足时 LLM 做什么，哪些操作不能靠改 YAML 获得

当规则候选低于配置下限，constructor 可补充 same_metric 关系。它必须引用已有的确切 fact_id；关系经校验后仍交给同一个类型化规则 planner。LLM 不直接决定自由算式或改写披露值。

默认允许 subtract、percent_change、ratio、average、abs、equals、and；公式注册表还限制 generator 与 operation 序列的合法搭配。自定义 YAML 可以启用 / 版本化已支持结构，但不能仅靠写一个任意新 generator 或 operation 链扩展执行能力。

min_depth=2、max_depth=4 是门槛。当前内置拓扑实际为 1–3 层，默认合格图为 2–3 层；提高 max_depth 不会自动产生更长研究链。DAG 深度也不等于模型调用轮数或工具步数。

实现：entity.pydag.py内置公式注册表replay.py

Realize only after replay

06 · 从答案图到自然语言研究问题

问题表述可以由模型变化，但图、证据和答案已经固定。独立语义 auditor 与确定性程序分别处理不同类型的错误。

constructor 看见什么

seed、具体 task_spec、cutoff、语言要求，以及不含事实 / 来源 ID、locator 和披露数值的 graph_summary。摘要含实体、期间、指标、事实角色、公式和 operation_count。

本例问题可以实现为：

“根据云帆科技年度披露，2025 年相对 2024 年的营业利润率绝对变动幅度是多少？请以比率小数表示并给出依据。”

问题应固定对象、期间、口径与 requested_output；最终 query 不附答案、证据正文或隐藏图。

两类审核如何配合

  • 语义 auditor：支持性、唯一性、金融含义、不泄漏、未复制 seed。它可以看到私有证据和答案作审核。
  • 本地确定性门：重新执行 DAG，核对 evidence 集合、答案值与 unit / scale / currency、深度和来源数。
  • 表述检查：长度、内部 ID / 来源 locator 泄漏、披露数字或答案泄漏、与种子 / 评测题近重复；语义审核另检查来源细节暴露和表述问题。
  • 最终 validation：对 Atomic / long_horizon 成品再运行确定性审计，输出 accepted / rejected 与原因。
技术细节：时间截断、评测去污染与审核失败

cutoff 不是把所有原始语料先删掉：normalize / dedup / facts 不按日期裁剪；v3 graph_planning 排除来源可用日期晚于 cutoff 的 facts，query_realization 再检查一次。普通任务可保留无有效日期证据；time_sensitive 任务要求全部证据有日期，且问题显式包含 cutoff 字符串。

冻结 corpus 同样排除未来 chunks，记录但保留 undated chunks；time_sensitive 执行再启用 dated_only。指定 available_at_field 缺失或非法时视为 undated；该字段有效时再与 published_at 的有效日期比较取较晚时间，避免把报告期当作公开可用日。

evaluation_file 支持 question / prompt / text 字段，构建本地 QuestionIndex；按项目的文本近重复度阈值 overlap_threshold=0.82 排除相似问题。它是基于文本重合的门，不能宣称排除所有语义污染；未配置评测集时无法执行该项对照。

独立语义 auditor 必须通过 answer_unique、fully_supported、financially_valid、non_exposing、seed_not_copied 五项。require_independent_auditor: true 要求 constructor 与 auditor 的模型身份不同，但不能保证两个模型不会共同出错。

候选不合格时被过滤；抽取、LLM 调用、问题审核等阶段有相应 quarantine 或汇总统计，规则枚举内的淘汰不保证逐候选留档。当前流程不会让 auditor 自动修复候选后直接放行。合格任务量与失败比例仍需满足发布门槛。

实现：questions.pyaudit.pydecontamination.pysnapshot.py

A second synthesis branch

07 · Atomic：给定上下文的局部能力数据

Atomic 与长程任务共享抽取事实，但不进行同一实体多来源检索任务的规划。它在单个 chunk 内构造局部问题，并给教师直接提供 context。

任务构造

chunk + 本块 facts → constructor → 图回放 → auditor → 本地复核

默认每个 chunk 尝试 2 条任务，稳定轮换 knowledge、extraction、calculation、analysis、verification 五类能力。候选含 input.context / question、answer、evidence_ids、evidence_graph、reasoning_trace。

本地图只允许引用当前提供的 facts；检查答案、维度、推理轨迹与证据一致性。无有效事实、构造失败或审计不通过时，该 chunk 可不产生样本。

教师解答生成

context + question → 自然语言与可见 CoT → 内容审核及计算回放 → LLM judge

默认各教师采样 2 个自然语言解答，私有审核提取实际推导并重算，再由 judge 按正确性、完整性和清晰度择优。

教师只看到 context 与 question，assistant 保留实际可见推理和答案。已审核参考 r 经复核后作为独立来源入样，可配置抽样比例，同任务共享 split。

Atomic 的 teacher JSON 生成与长程 agent_runtime 是两个接口；目前 native / strands / codex / claude_code 的 runtime 选择用于长程教师执行，不能写成 Atomic 同样经过四种 CLI agent loop。

实现：atomic.pyatomic_teacher.pyformatting.py

Teacher execution and trace collection

08 · 强模型 agent 如何生成长程轨迹

合成任务已经有私有答案图；教师收到 query 和公开执行条件，自行选择检索与计算过程。Strands、Codex、Claude Code 均可选金融工具或框架原生工具，结束后采用相同的隐藏答案与证据约束验收。

1 · 公开输入问题、可用工具、剩余预算；隐藏答案图不进入模型输入
2 · search_corpusSQLite FTS5 检索同一实体、截止日前的冻结语料
3 · open_chunk打开命中正文，取得可引用 quote，记录实际取证
4 · calculate执行允许的计算；可继续检索与打开，直到预算终止
5 · 最终证明提交 facts / steps / answer，私有 verifier 校验后决定接受

上图是 finance 金融工具模式 的典型路径。教师可多次搜索、打开与计算，也可直接在证明中给出可回放步骤；并不强制调用 calculate 才算完成。成功标准是已取得必需证据并提交正确证明。

原生工具模式的另一条执行路径：query + 冻结语料目录 → Codex 自带 shell / 文件工具，或 Strands 官方 file_read / shell，或 CC 自带 Read / Bash → 正常最终回复中的自然语言推导和答案 → 读取与文件完整性核对 → 隐藏图离线校验。此路径不创建金融 session / bridge / MCP，也不注册 submit_final；保留框架本来的工具名、schema 与 system。

三层记录，分别回答不同问题

  • 模型 HTTP：请求、响应、SSE 原始字节和时间，解释模型实际收到和返回了什么。外部 runtime 自动经采集代理连接后端。
  • SDK / CLI：事件、消息、退出状态、错误与超时，解释运行框架如何推进 agent loop。
  • 证据与校验：金融模式保存动作、observation 和证据账本；原生模式绑定真实文件读取、返回文本及文件指纹。两者保留私有 verdict。

单靠 vLLM / SGLang 服务日志通常只能看模型调用侧；完整 agent 轨迹还需拼接工具与环境执行记录。运行 ID、attempt 引用与文件索引负责关联。

统一验收，执行路径各自保留

金融模式的外部 runtime 通过 submit_final(answer) 提交，项目 JSON runtime 使用 final 动作；原生模式从框架最后正常回复取得实际解答，并唯一绑定到实际模型响应。

教师不受固定 proof schema 约束。审核 JSON 与候选图仅在后台使用；来源必须实际取得，回放候选自身计算并认可等价路径。可恢复错误允许继续，错误、重复、无贡献动作及关联推理屏蔽 loss。

两种模式都检查答案、来源和完整证明。原生模式还核对未改写的语料文件、读取调用 ID 与真实返回，不接受用打印引文伪造读取。CLI 返回 0 或 SDK 自然结束本身不足以接收样本。

技术细节：冻结检索、教师采样、mask 与运行边界

检索：corpus_index 保存截止日前及无有效日期的 chunks；retrieval_index 依实体事实建立 source 与 canonical_entity_id 的关联，复制关联来源的完整 chunks，包含未抽取出事实的片段，并建立 SQLite FTS5 trigram 索引，必要时使用 LIKE 回退。当前实现没有 embedding / 向量数据库。检索和打开限制 canonical_entity_id、cutoff，时间敏感任务另要求 dated_only。

金融工具契约：search_corpus(query, limit) 最多返回 10 条，带 chunk_id、source_id、日期和前 350 字符 snippet；open_chunk 只能打开之前搜索命中的 chunk，返回完整正文。calculate(operation, values) 支持 add / subtract / multiply / divide / percent_change / average，values 为 2–12 个数；它的操作集与隐藏 DAG replay 不完全相同，例如比率可用 divide 求值，最终解答无需复刻 gold 操作名称，候选运算仍须满足金融关系和正确答案。

原生工具契约：配置 codex.mode / strands.mode / claude_code.mode: native 启用相应框架的工具。语料包含该实体所有可见分块及干扰材料，公开清单只有来源、日期、路径、chunk ID 与指纹，不按 gold evidence 挑选。来源读取按原生 call ID 与后续工具返回绑定；任意脚本可辅助研究，但不能仅因输出含正确 quote 就作为已取证来源。精确可识别读取形式以离线校验实现为准。

上下文：native 将公开状态按 max_context_chars 打包；Strands 和 CLI 使用各自消息历史管理，因此不同 runtime 的模型可见上下文与行为不完全一致。不能直接承诺迁移 runtime 会提高合格率。

采样：长程按 long_teacher_roles 轮换尝试，总次数受 rollouts_per_task 限制；出现首条合格轨迹即停止。它不是对每种 runtime 完整采样后再全局择优。失败 / 超时尝试也记录在 trajectory-index 与 audit 引用中。

输出 mask：统一金融 long messages 中 system、user、tool_response 的 loss 为 false，模型实际文本保留为 assistant，工具动作使用 step_relevance。启发式屏蔽重复与部分无关操作，不精确识别所有无用计算。原生模式按每次实际请求分别保留上下文与响应，只将本轮模型输出标为监督目标，不套用金融工具的逐动作相关性 mask。

证明严格性：proof 必须覆盖整张 gold DAG，op、输入顺序、params、步骤值与维度均需匹配；所有 answer / fact / step 的 unit、scale、currency 都要显式填写，空值也需为 null。当前验证器不接受任意代数等价的替代推导。

隔离：金融模式由桥接器串行维护 session / SQLite；原生模式使用独立语料目录，不创建金融 session。CLI 使用临时 HOME，Codex native 保留 sandbox；Strands native 在子进程中隔离工作目录与工具环境。Linux 超时终止对应进程组并冻结记录。工具配置、只读语料与指纹核验不能代替操作系统隔离。

协议：同样是自部署模型，提供 /chat/completions 不代表已满足 Codex Responses 或 CC Anthropic Messages 的要求。后端须匹配 chat template、tool parser、流式事件与所需协议；当前项目不自动实现这些协议之间的通用转换。

记录范围：HTTP 采集只保留服务实际返回的数据，无法恢复模型未公开的内部思维、未返回的 token IDs 或 logprobs。项目 JSON native 保存完整请求 / 响应 JSON，可来自完整响应缓存，parsed 文件只是摘要；它与外部 runtime 的原始 wire capture 应分开说明。

实现：session.pyverifier.pycollector.pycli_runtime.pyruntime 配置说明轨迹采集说明

技术细节：标签、数据划分与发布顺序

query_export 的阶段产物在 stages/query_export/shards/000000/queries/，教师失败时已导出的 query 仍可使用。最终 export 产物位于 stages/export/shards/000000/，汇总启用的 query 与 SFT 分支并生成发布清单。

汇报时建议展示的漏斗与分布

输入记录 → 去重记录 → chunks → 有效 facts → 实体 → 规则图 / 补充图 → 通过语义审计的 task → validation 合格 → query → 教师尝试 → 合格 SFT。这些指标不一定逐项单调：一条记录可有多块、多事实，多条任务也可能共享事实。

LLM terminal error 的分母随阶段变化：facts 按 chunks，Atomic / query_realization 按候选，实体 / 关系补充按请求数；不能把 0.02 统一描述成所有 HTTP 调用失败率。validation 的 0.01 针对进入最终复核的任务，不是要求所有合成候选的淘汰率低于 1%。

同时统计：quote / 数值抽样准确率、实体误合并与冲突、按 formula 的深度和来源分布、各门拒绝原因、teacher runtime 合格率 / 时延 / token、无日期来源比例、train / val 来源重合和评测近重复。代码已提供多项计数与审计产物；人工准确率和分组泄漏分析仍需另外组织抽样统计。

Scope and factual claims

11 · 对外说明时需要保留的边界

文档展示已实现机制，不把研究动机、测试替身或可配置上限当作已经验证的线上能力。

方法实现

采用“证据约束、先答案图后问题、双重审计、教师执行”的合成流程。公式、prompt、近似种子、证明格式属于工程实现，不能宣称逐字复现未公开的官方数据与内部 harness。

执行兼容性

四种 runtime 已有适配代码与本地测试；真实 Linux SDK / CLI + 所部署模型的完整联调仍需验收。尤其 Codex 与 CC 的协议不能仅凭后端提供 OpenAI Chat 接口推断兼容。

任务与训练

本项目产出 query、证明、SFT messages 和轨迹；Slime 的 adapter / 采集做法仅供参考，没有在这里运行 Slime、RL 优化、奖励更新或学生参数训练。

适合汇报的一句话：系统以真实语料事实为证据底座，用分析师种子约束可执行 DAG，先计算可回放答案再生成问题，经过语义与确定性审核后，按需采集强模型 agent 的真实执行过程，输出相互关联的 query、SFT 样本与审计轨迹。
