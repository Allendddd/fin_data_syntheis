Record to auditable task

一条原始数据，如何变成可回放的金融训练任务

从 JSONL/Parquet 的一行开始，先建立稳定来源定位，再抽取事实。atomic 任务在本地 chunk 内构造；long-horizon 任务把同一金融实体的多份来源汇合成答案 DAG，回放答案后才生成自然语言问题。

0 → N一条输入可能产生零个或多个任务
6,000默认单 chunk 最大字符数
≥ 2长链任务默认独立来源数
2–3当前默认成品 DAG 的实际深度
◎
先明确“单条数据”的含义。它是一条带 text 的输入记录，是追踪和抽取的起点，不是最终样本的固定单位。无有效事实时产出为 0；一个 chunk 可以产生多条 atomic 任务；一条记录中的事实也可以参与多个 long-horizon 图。
Shared front half

所有任务共用的前半程

这部分先解决输入是否可信、能否定位、是否重复，以及哪些句子可以成为后续推理的事实叶节点。

示意输入：JSONL 中的一行

{
  "id": "report-a-2025",
  "text": "A 公司 2025 年营业收入为 120 亿元，\n同比增长 20%。",
  "title": "A 公司 2025 年年报",
  "published_at": "2026-03-20",
  "ticker": "000001"
}

此例假设配置了 input.id_field: id，并把 title、published_at、ticker 列入 metadata_fields。

什么情况下这条记录会在前半程被隔离？
缺少或错误类型的 text、正文超过配置上限、JSONL 单行超过字节上限、external ID 与另一正文冲突，或事实抽取结果不能被原文 quote 与字符区间支持。记录级错误进入 quarantine.parquet；系统级 I/O 或输入指纹变化会让 shard 失败。
Two products

事实抽取后，分成两条合成产线

两条产线共享可定位事实，但上下文形式、组合范围和难度约束不同，最后在 validation 阶段重新汇合。

Atomic：单 chunk 内的能力任务

用户输入中带原文 context，目标是训练知识、抽取、计算、分析或验证等局部能力。

A1
选择 chunk 与本块 facts默认每个 chunk 尝试构造 2 条任务，能力类型按稳定规则轮换。
A2
Constructor 生成候选输出 question、answer、evidence_ids、evidence_graph 和 reasoning_trace。
A3
本地预回放图必须只引用已抽取 fact_id，运算结果必须可由 Decimal 执行。
A4
独立 Auditor检查答案是否被证据支持、问题是否清楚、推理是否泄漏内部字段。
A5
确定性复核重新回放图并校验答案、证据集合、数值维度与推理步骤。

Long-horizon：同一实体的多来源任务

问题本身不附原文 context，任务通过 source pack 关联多份证据，并要求先固定答案图。

L1
实体解析强标识符 → alias → 规范化名称 → 受约束 LLM fallback。
L2
按 canonical entity 重分区同一主体散落在不同文件和原始 shard 的事实被送到同一个 planner。
本条记录的 facts ＋ 同一实体的其他来源 facts（默认至少 2 个 source_id）
L3
公式规划 DAG匹配期间、metric、unit、scale、currency 与来源宽度，构造类型化图。
L4
确定性回放答案先计算 terminal，拒绝除零、维度冲突、断开节点和伪深度。
L5
问题实现与审计按 seed/task spec 生成自然问题，再由 auditor 与本地门共同验收。

Provenance chain

从成品可以追溯回原始行

这些 ID 逐层固定数据血缘；最终任务中的 evidence_ids 与 terminal 的事实祖先必须完全相等。

source_uri哪个 JSONL / Parquet 文件
source_locator行号、字节区间或 row group / row
record_id规范记录与正文哈希
chunk_id正文字符起止位置
fact_idquote、数值与金融维度
graph_id / task_id公式版本、回放轨迹与答案
Acceptance gates

最后怎样决定“收下”还是“隔离”

validation 同时读取 atomic 与 long-horizon 成品，再运行一次本地确定性审计。通过后才能进入 export。

检查层必须满足失败结果
输入记录text 类型/长度正确，来源可定位，输入指纹未变化记录隔离或 shard 失败
事实quote 在原文中，数值可解析，字段长度受限，字符区间有效fact_rejected
证据图无环、无断开节点、输入不重复、单位与币种兼容、答案可回放候选图丢弃
语义审计问题清楚且被证据完整支持，不泄漏答案或内部定位字段quality_rejection
最终发布全局错误率不越阈值，有效任务数达到下限，全部 shard 完成阻止 export / 发布
通过Parquet 为规范产物，可选 JSONL；清单记录文件大小与 SHA-256写入 _PUBLISHED.json

Atomic 成品的核心结构

task_type: atomic
input: {context, question}
answer: {value/text, unit, scale, currency}
evidence_ids: [fact_id, ...]
evidence_graph: {nodes, terminal_id}
reasoning_trace: [...]
semantic_audit: {...}
verification:
  accepted: true
  replay: {depth, fact_ids, source_ids, trace}

semantic_audit: {...}
