1. 默认 harness 改为 Codex，继续支持配置其他 harness。
将配置缺省值、示例和文档统一为 Codex。保留已有其他实现及显式配置的兼容性。任务、教师模型配置、检索模式、资源范围和审核规则独立于 harness；切换 harness 只改变实际执行、轨迹、作答、用量及其派生审核结果。通过适配器处理不同工具协议，不因工具名或消息格式不同改变金融正确性的判定。

2. 明确任务合成与教师生成的边界。
先生成并保存任务，再独立采集 atomic response 或长程轨迹；两阶段可以属于同一个 run。
atomic 教师只接收已保存的 c、q；长程教师只接收已保存的 q，以及工具、预算、时间边界和资源入口等公开执行配置。
y、E、r、Mlong、原始种子及隐藏证据图留在后台，不进入教师提示词或可访问工作区。
生成阶段不重新抽取事实、规划图或合成 query。同一批冻结任务支持更换模型或 harness 后重新采集。
区分任务产物指纹与采集配置指纹；采集缓存包含模型、harness、参数和资源版本，避免错误复用。兼容现有 run 的不可变校验，不删除旧成果、清理成功标记或绕过签名检查来续跑。

3. 新增独立于 harness 的互斥检索模式。
使用 harness.retrieval.mode: static | web，静态原文件目录使用 harness.retrieval.corpus_path。原始库真实路径由用户另行配置，不写死路径。
static 模式只从配置的文件库取证；web 模式联网取证，不挂载、不查询静态语料库，也不回退调用 search_corpus/open_chunk。
各 harness 应遵守相同模式边界。不支持某个模式时提前明确报错，不能静默替换 harness、模型、资源或检索方式。后台审核仍可读取隐藏参考资料，但不能将其作为工具结果提供给教师或冒充教师取得的证据。

4. 静态模式提供原始文件访问。
支持用户目录中的 PDF、DOCX 等原始材料。解析文本、分块和 SQLite 可以作为内部索引，但不能继续用分块 TXT 替代完整原文件。
保持现有合成输入链路。两套语料库不必整库逐条配对，不要求用户先提供跨库映射表；只对任务实际使用的来源与事实建立可验证的对应关系。已有原文件标识、URL、哈希可直接复用，不同来源则核对实体、期间、口径和事实。记录实际原文件哈希、版本、来源日期及页码、段落或表格定位。不要把输入 JSONL/Parquet 的 source_uri 误当作原 PDF 路径；不能伪造定位或对应关系。
检索范围由公开资源配置决定，不能依据隐藏答案图预先挑出必读文件或检索路径。支持复用原文件库，不要求每个任务复制整库。agent 可使用工作目录计算，但不能修改作为依据的原文件。

5. 接通真实 web search 与网页证据采集。
移除全局硬编码关闭搜索的限制，按当前 CLI、SDK 和模型端点实际支持的能力接入可配置搜索与读取工具，并适配相应轨迹事件。
web 模式保留所选框架的原生 system 和工具空间，不限制只能用 search_web/read_web 或 finance MCP。审核和导出不得按工具名白名单拒收。search_endpoint 配置搜索工具的执行后端：未设置时保留原生后端，设置后须绑定对应 harness 的标准搜索入口，不是另外增加一个可选工具。Codex 绑定原生 web.run 的 standalone 搜索 RPC，CC 绑定原生 WebSearch 的独立搜索请求，Strands 绑定选定 SDK 搜索工具的执行函数并保留其工具名/schema；没有默认 SDK 搜索入口时可注册该入口。旧 JSON runtime 的既有 search_web 共用后端实现。其他工具继续可用，第三方 MCP 或脚本自管的后端不宣称已被此参数接管。显式指定后端后，不得静默旁路到原托管搜索；无法绑定或原生协议不兼容时明确报错。
增加明确的后端协议配置，至少区分 Tavily 兼容请求和通用 JSON 搜索服务；URL 本身不代表协议。记录计划绑定、运行时实际绑定、实际请求端点与失败原因。保留原始模型字节；搜索服务 RPC 单独标记并作为工具观察，不当作教师模型输出参与监督。对各 harness 验证真实工具调用确实请求配置端点，并验证其他工具可用、无原生后端旁路、失败不回退、没有重复注册竞争搜索入口。真实 CLI 加模拟模型/后端的测试与真实 GPU 冒烟分别报告。
记录实际搜索请求、返回结果、读取 URL、实际返回内容、获取时间、可核验的来源时间及内容哈希。仅有链接或标题不能视为已经取得金融证据。
保存联网结果用于审核和重放，区分 agent 实际收到的内容和后台独立核验材料。原生托管搜索可能只公开 URL 或引用片段；可以对实际返回的 URL 另抓网页核验，标记 verifier_snapshot，但不得将后台正文伪造成工具观察、写回教师轨迹或补写模型缺失推导。无法核验来源与引用时拒绝候选并记录原因，不要求模型改用指定工具。支持一次模型响应内出现托管搜索、工具结果和最终作答，工具观察、引用元数据及不透明内容不参与预测 loss。
时间敏感任务按已冻结的截止时间、实体、期间和口径审核。抓取时间不等于发布或有效时间，不能用最新网页自动改写参考答案。无法取得符合任务要求的证据时，记录明确原因，不回退静态库。
检索模式与内容归档是两个职责：web 执行走联网入口，归档供后台使用。

6. 补齐与 harness 无关的证据审核。
在现有实际交互绑定与候选推导回放基础上，补齐候选事实和金融关系与原任务 E／P0／Gy 的对应检查。验证原始来源、实际取得的内容、期间、单位、尺度、币种、中间计算和最终答案。
不能只凭最终数字正确、审核模型返回 accepted=true 或候选计算可执行就放行。审核器不能借助参考答案替教师补写缺失步骤。
允许有依据的等价证据表示、单位换算和替代推导，不要求事实数量、节点命名、步骤顺序或图拓扑逐项相同；同一公司的不同时期、不同口径或不同版本不能自动视为等价。
原文件和网页通过来源定位与事实映射审核，不要求它们携带旧静态库的 chunk_id。
保留统一的整样本筛选和逐轮 loss 筛选语义，通过适配器处理各 harness 的原始记录。分别记录采集／协议问题、证据缺失、答案错误、推导错误和语义审核不确定等原因，并明确哪些检查由程序完成、哪些依赖模型判断。

7. 种子输入简化为 query，内部自动解析。
正式入口支持 JSONL，每条只需 {"query":"研究请求"}，兼容已有 seed_query、text、question 字段。不要求用户提供答案、轨迹或 task_spec_template。
自动生成稳定种子 ID，并在任务合成前解析任务目标、必要事实、推导结构、时间约束及输出要求，保存并缓存内部规格，避免各分片重复解析。保留研究意图，移除具体实体和数值对新任务的绑定。
修改当前预检和规划入口对手工模板的依赖，避免用固定英文关键词或角色字符串硬匹配代替种子意图理解。无法表达的任务类型明确报告能力缺口，不能偷偷改成另一种任务，也不能降低深度或来源门槛凑样本。
区分真实分析师种子、人工示例和模型扩写来源；内置五个近似模板明确标记为示例，不能冒充论文种子库。种子用于合成 query，不再作为轨迹生成提示词。
对种子和生成 query 做去重及评测隔离。未配置评测集时如实记录未执行；不要宣称已完成评测去重，也不要把词面近似检查宣称为完整语义去重。
