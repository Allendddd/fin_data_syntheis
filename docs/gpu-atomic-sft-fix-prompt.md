重点核对 §3.1、§3.2、§4.1、§5.1、§5.2。原论文未公开具体 prompt、parser、judge rubric 和完整 harness，不要把工程选择描述成论文硬性要求。

一、修改目标和边界

任务构造阶段继续保留内部 facts、参考推导 r、答案 y、证据图及审计 JSON。工具调用继续使用实际接口需要的参数 schema。

需要移除的是：教师最终解答必须采用固定 PROOF_SCHEMA JSON、候选必须逐节点复刻隐藏图、以最短 JSON 替代质量择优，以及因此产生的错误过滤和错误 SFT 监督。

atom 的教师应依据 context＋question 生成解答。长程 agent 应在环境中检索、读取、计算，形成真实交互轨迹并正常提交研究结论。两者最终响应均应支持自然语言推导和答案。

不要顺带重构 query 构造、扩展公式库、降低图深度/来源广度门槛、增加联网检索或实现模型训练。长程纯 query 与隐藏校验资料分离的导出方式继续保留。

二、atom 教师生成与文本请求

1. 教师只接收正常 system 指令、context 和 question。要求给出问题所需的金融推导与最终答案，使用合适语言；不强制 JSON、固定字段、固定结束标记、固定步数、逐字引用或固定解法。
2. 教师输入不得包含隐藏答案、参考推导、内部证据 ID 或证据图。
3. 在 OpenAI-compatible 客户端和 ConfiguredRoleClient 中增加文本 completion / 完整 exchange 能力。文本请求不发送 JSON response_format，不执行 JSON 解析，即使共享 endpoint.strict_json=true。
4. 保持内部 complete_json 和其他调用方的兼容行为，不能全局关闭 JSON 或强行把所有 runtime 接到同一个文本 API。
5. 保存教师实际返回的 reasoning、content 和完成状态，不补写、摘要、修复或替换教师解答。单独返回的 reasoning 与最终 content 必须有明确、可追溯的保存和训练表示。

三、内容校验与输出格式解耦

1. 设计独立于教师输出格式的私有校验流程。可使用独立 LLM 审计请求提取和核验语义、证据及计算，再结合本地执行器验证；不要求教师输出验证器内部结构。
2. 检查答案等价性、证据支持、必要推导完整性、金融关系、实体、期间、单位/尺度和矛盾。不能仅凭 accepted=true、最终数字命中或关键词出现就放行。
3. 审计器只能解释教师实际写出的推导，不能借助隐藏答案或参考图补齐教师未给出的必要步骤。
4. 对可执行计算，回放候选自身的计算路径。核验来源引文在允许的 source/context 中、教师引文在真实响应中、数值和中间结果与实际内容对应，并检查计算、维度和结论。
5. 不要求候选节点数、事实集合、操作名称、步骤顺序及依赖结构与参考图逐项相同。认可有依据的等价运算与单位表示，例如 add 与 sum；不能因序列化差异拒绝。
6. 长程仍需满足任务规定的金融关系、隐藏参考答案和证据支持要求，不能放宽成“从任意地方得到正确数字即可”。证据必须来自 agent 在本次轨迹中实际获得、且处于允许快照与时间边界内的观察。
7. 知识、抽取、文本分析、验证等能力按问题实际需要检查，不强制添加算术步骤。无法纯数值回放的部分采用有来源锚定的语义审计，明确记录其依赖与局限。
8. 结构化审计、提取图和 judge 输出仅用于私有验收及 sidecar，不作为教师原文，也不进入模型输入。无法可靠核验时明确拒绝并记录原因。

四、atom 模式过滤、择优与参考推导 r

1. 对空响应、截断、明显重复步骤、大量重述 prompt、没有可用答案和无依据推导做内容过滤，不添加固定长度、英文答案标记、编号样式或最短答案等门槛。
2. 默认 atomic_selection_policy 使用独立 LLM judge。多个合格候选按推导完整、证据支持、金融正确和清晰度择优，不能按字符数替代。单个合格候选可直接选择。
3. judge 失败或返回无效 candidate_id 时明确拒绝，不能静默回退到最短或首个。兼容旧 concise 时，将其作为 judge 的明确弃用别名并记录迁移；如保留 first_valid，必须标明它是显式启用的非论文择优模式。
4. 根据 §5.1，把已审核的原始参考推导 r 作为明确的数据来源纳入 SFT，而不是只在教师失败时作为 fallback。论文模式应支持选中教师解答与参考 r 共同构成数据；是否纳入及混合方式应可配置，具体比例不得宣称来自论文。
5. 参考 r 必须来自已审核的构造记录，明确标记来源；不能伪装为新的教师原文，不能仅拼接 gold 答案补足样本。r 缺失或未通过检查时记录原因。
6. 同一任务的教师样本和参考样本必须划入同一 train/val split，正确维护多样本计数、样本标识和 sidecar 对应关系。
7. 可配置 atom 的 verifier/judge 角色，提前校验角色存在。独立评审指独立请求，不额外要求不同供应商或不同模型。

五、长程最终提交：覆盖所有 runtime

逐一核对并打通以下路径，不能只改一处 system prompt：
- 项目自有 native JSON action runtime；
- Strands、Codex、Claude Code 的 finance/MCP 模式；
- Strands、Codex、Claude Code 的 native 原生工具模式；
- 最终响应解析、离线审计与 SFT 导出。

1. 自有 JSON action runtime 可保留 tool/final 控制包络，但 final 应承载实际自然语言解答，不能再要求其内容是 proof JSON。
2. finance 模式可以保留最终提交动作，但提交内容应支持真实自然语言解答；同步修改 bridge 的工具参数、解析器和轨迹绑定，不能只改工具描述。
3. 原生工具模式使用框架原生工具及正常最终回复，不注入强制 proof JSON 或自定义最终提交工具。
4. 原生回复、finance 提交和自有 action 提交均需进入统一的内容验收原则；保留各自真实工具协议和请求/响应，不伪造工具、观察或推理。
5. 不把 atom 的多候选 LLM judge 择优额外强加给长程。长程按 §5.2 实现轨迹验收和逐轮监督筛选。

六、长程错误恢复与逐轮 loss

1. 区分可恢复的工具/动作错误和不可恢复的环境错误。可恢复错误作为 observation 返回，允许 agent 在预算内继续，不因第一次工具错误立刻丢弃整条轨迹。
2. 去除“invalid_actions 必须为 0”作为所有合格 SFT 轨迹的统一条件。成功恢复且最终答案、证据和执行满足要求的轨迹可以保留；错误动作仍需单独记录和屏蔽监督。
3. 超预算、无最终回答、来源越界、环境损坏或不可恢复错误继续按对应失败处理，不静默放行。
4. 按 §5.2 对重复且没有新证据、无助于任务推导、调用不存在工具等动作屏蔽 loss。它们及观察仍保留在后续条件历史中。
5. 对相关 assistant 轮次或内容块落实一致的筛选，不只屏蔽工具参数、却继续训练同一无效动作的相关生成文字。
6. 覆盖规范化 messages 和三个原生数据格式的 loss mask；所有环境观察和输入上下文均不作为预测目标。
7. 多动作响应按输出格式支持的粒度标注，不能使用首个工具调用的 mask 覆盖其他调用，也不能静默把全部内容设为 loss=true。不得通过删掉历史或重写教师文本解决格式问题。

七、原生读取与证据绑定

1. 检查 cc_workspace、native_capture 等路径，修复“只识别简单绝对路径 cat 等少量形式”导致的误拒绝。
2. 对可可靠解析的相对路径、workdir、常见读取命令、框架 reader 输出及部分读取，正确绑定到实际文件、返回内容和冻结快照。

4. 不能仅凭参数出现路径就当作已读取。必须确认调用成功、返回内容实际包含相关证据、观察先于最终回答、来源和时间合法，且源文件未被篡改。
5. 无法可靠绑定的形式应给出准确原因，不伪造 read binding，不把失败命令输出、模型复述或未观察内容算作证据。
