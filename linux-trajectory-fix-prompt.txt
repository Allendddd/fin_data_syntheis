请修改 Linux 环境中当前 mint-synth 仓库的长程教师轨迹采集与 SFT 导出流程，保留教师实际输出的分析、规划、反思、工作笔记及工具交互。

先阅读 AGENTS.md 和当前实现，再实施修改。以 Linux 工作区实际代码为准，保留已有功能及用户改动。

一、需要解决的问题

当前 long-train.jsonl 主要包含：
system/query → tool_call → tool_response → …… → 最终 proof。

需要核查并修复两个阶段的信息丢失：

1. 模型响应解析阶段：complete_json 可能只返回解析后的动作 JSON，没有保留 reasoning_content、JSON 外的分析文本和完整原始响应。
2. 轨迹归一化阶段：normalized_sample 主要从环境执行 trace 提取工具名、参数、观察和最终 proof，没有完整保留教师的分析、规划、反思文本，动作中的 memory 字段，以及 SDK/CLI 中独立的 assistant 消息。

目标是导出教师完整、可追溯的研究交互，不能仅导出工具执行记录，也不能只修改提示词就宣称完成。

三、完整采集模型交互

每次逻辑模型调用至少保存：
- 实际请求消息、工具定义和采样参数。
- 模型完整响应。
- 接口实际返回的分析/推理字段、普通文本和工具调用。
- 解析后的环境动作及对应的工具执行结果。
- 调用标识、顺序及是否来自缓存。

原始响应与解析结果分开保存。执行器可以只消费动作，但采集端不能因此丢弃响应的其他内容。

对于流式返回，保留实际事件顺序；非流式返回应保留字段及同一响应内的关联，不伪造时间顺序。

只保存模型接口实际提供的内容。没有返回分析时，不补写、不重建，不从隐藏答案图生成“教师思考”。模型未暴露的内部推理不能假定可获取。

保持现有事实抽取、构图、审计等 complete_json 调用的功能，避免为长程轨迹需求破坏其他阶段。

四、从完整模型交互导出 SFT

训练数据应表达实际发生的顺序：
用户问题 → 教师分析/规划 → 教师工具调用 → 工具返回 → 教师对结果的分析及下一步行动 → 后续调用与返回 → 最终回答或 proof。

具体要求：
- 普通 assistant 文本与工具调用都保留。
- 分析与工具调用属于同一次响应时，保留其关联。
- 不要求每次调用前必须存在分析文本；模型只返回工具调用时，应忠实保留。
- 不得把分析、工具调用和最终回答挪到与实际交互不符的位置。
- 归一化允许转换目标模型所需的格式，但不能仅从环境 trace 重建对话，省略已有的模型文本。
- native 每轮输入的状态 JSON 也要留档，不能把归一化样本描述为逐字原始对话。

优先保持现有 ms-swift messages/tools 数据契约：
- assistant：教师实际返回的分析、规划、工作笔记或最终内容。
- tool_call：教师生成的工具调用。
- tool_response：环境返回。

明确 reasoning_content 等字段如何映射到目标模型的训练模板，避免重复插入或错误包裹推理标记。

五、memory 的处理要求

memory 是教师可选输出的工作笔记，可能包含 plan、confirmed、unresolved。它与 API 的 reasoning_content 是不同内容，不能互相替代。

必须区分原始留档与训练导出：
1. 原始轨迹完整保存教师实际返回的 memory，以及下一轮实际提供给教师的 working_memory。
2. 如果教师把规划写在 memory.plan 等字段中，这些实际输出也应进入最终训练样本，不能仅留在审计文件就算完成规划信息的保留。
3. 训练表示应与学生使用的协议一致。若学生使用相同的 JSON 动作协议，则保留真实动作中的 memory；若转换为工具调用协议，则为实际工作笔记定义明确且可追溯的消息表示，保留原文，不冒充 API 推理字段。
4. 不把 harness 合并或生成的状态伪装成教师新输出，也不重复监督同一段笔记。
5. 教师没有输出 memory 时不强制添加，不补写字段。
6. confirmed 只是模型笔记，仍需独立证据校验，不能作为标准答案或已验证证据。

六、协议、缓存与校验一致性

1. system 必须与导出的目标协议一致。使用原生工具调用格式时，不应同时要求输出 {"tool":...} 文本动作；最终直接输出 proof 时，不应要求 {"final":"..."} 包装。
2. system、user 和工具观察不参与 loss。已有无关或重复动作的 loss 屏蔽可以保留，但不要靠删除整轮消息实现。对教师输出的分析、工作笔记及工具动作，明确损失策略并验证实际训练模板能够正确处理。
3. 升级长程轨迹缓存格式或命名空间。旧缓存若只有 parsed JSON，不能冒充完整响应；明确标记或重新采集，不覆盖原始历史产物。
4. 保持隐藏答案图、标准答案和私有校验结果不进入模型输入。
5. 保留现有答案、证据、单位、截止日和动作有效性校验，以及已有 abs 等工具能力。
6. 原始模型交互、环境轨迹、训练样本之间有稳定关联；发布后能从一条样本定位到其原始模型调用。
7. 各现有 runtime 应保留其实际可获取的模型内容。尚未支持完整导出的路径必须明确标记，不能静默退回仅含工具的样本并宣称完整。

七、测试与验收

增加针对实际信息丢失风险的测试，至少覆盖：
- 响应同时包含 reasoning_content 和动作内容，两者均保留。
- 响应包含可解析动作 JSON 及其他文本时，原始文本不会因解析而丢失。
- memory.plan 等实际教师输出既保留在原始轨迹中，也按规定进入训练样本。
- 分析、工具调用、工具观察的顺序及对应关系正确。
- 模型没有返回分析或 memory 时，不生成虚构内容。
- 缓存命中后仍能获得完整交互；旧的仅含 parsed JSON 的缓存不会被误认为完整。
- SDK/CLI assistant 消息能进入训练导出，而不只是金融工具 trace。
- 导出 system 与工具调用及最终回答协议一致。
- 隐藏校验信息不泄漏，原有金融校验仍然生效。

使用可控模型响应或 HTTP mock 验证采集和导出；明确这些测试不代表真实模型服务验证。若有可用服务，再做小规模端到端验证。
